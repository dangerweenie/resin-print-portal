# Fetching members + activation status (A/I/S) from tinkerAccess

## Summary

On the `dstearns/rust-server` branch there is an existing endpoint that returns a
JSON list of members with their activation status. **No code changes are needed.**
It is the Leptos `#[server]` function `get_users`, defined in
`tinker-access-server-rs/src/users.rs` (lines 6-26) and auto-registered as an HTTP
route by `leptos_axum` when the Axum router is built in
`tinker-access-server-rs/src/main.rs` (lines 29-41).

The legacy Python/Flask server (`server.py`) has **no** JSON roster endpoint - it
only renders HTML admin pages (`/admin/interface/user` for A+S users,
`/admin/interface/inactiveuser` for I users), gated by a `password` cookie.

## The `get_users` endpoint

| Field        | Value                                                            |
| ------------ | --------------------------------------------------------------- |
| Method       | `POST`                                                          |
| URL          | `http://127.0.0.1:3000/api/get_users11102523982452806591`      |
| Content-Type | `application/x-www-form-urlencoded`                            |
| Body (all)   | *(empty)*                                                      |
| Body (filter)| serde_qs array form, e.g. `status_filter[0]=A&status_filter[1]=I&status_filter[2]=S` |
| Response     | `application/json`                                            |
| Auth         | none currently enforced                                       |

### Response shape

JSON array, one object per member (serialized directly from
`entities::user::Model`, see `tinker-access-server-rs/entities/src/user.rs`):

```json
[
  { "id": 1, "name": "Jane Doe", "code": "12345", "status": "A" },
  { "id": 2, "name": "John Roe", "code": "67890", "status": "I" }
]
```

- `name` and `code` may be `null`.
- `status` is exactly one of `"A"`, `"I"`, `"S"`.

### Status meaning

Per `docs/API.md` and `docs/OLD_API.md`:

| Code | Meaning                     |
| ---- | --------------------------- |
| `A`  | Active                      |
| `I`  | Inactive                    |
| `S`  | Active + 24-hour access     |

### The URL hash suffix

The path is `/api/` + function name + a collision-avoidance hash generated by the
`#[server]` macro. The hash `11102523982452806591` was extracted from the compiled
WASM bundle (`tinker-access-server-rs/target/site/pkg/tinker-access-server-rs.wasm`).

**It can change** if `get_users` is moved to a different module or if
Leptos / `server_fn` (currently 0.8.x) is upgraded. If the request returns 404,
recover the current path by either:

1. Loading `http://127.0.0.1:3000/admin/interface/user` in a browser and copying
   the `/api/get_users...` request URL from the Network tab, or
2. `strings tinker-access-server-rs/target/site/pkg/*.wasm | grep 'api/get_users'`

## Running the server

Requires a `db.sqlite` file with the existing `user` table schema
(`id INTEGER PRIMARY KEY, name TEXT, code TEXT, status CHARACTER(1)`).
`DATABASE_URL` defaults to `sqlite:./db.sqlite`.

```bash
cd tinker-access-server-rs
cargo leptos watch          # or: cargo run --features ssr
```

## Example calls

All members:

```bash
curl -sS -X POST http://127.0.0.1:3000/api/get_users11102523982452806591 | jq .
```

Only inactive members:

```bash
curl -sS -X POST http://127.0.0.1:3000/api/get_users11102523982452806591 \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  --data 'status_filter[0]=I' | jq .
```

Active and 24-hour members:

```bash
curl -sS -X POST http://127.0.0.1:3000/api/get_users11102523982452806591 \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  --data 'status_filter[0]=A&status_filter[1]=S' | jq .
```

## Related endpoints (not roster lists)

- `get_users_for_device` (`tinker-access-server-rs/src/devices.rs`) - POST server
  fn; returns each user trained on a device, including the full user model (so
  also has `status`).
- `set_status_user` (`tinker-access-server-rs/src/users.rs`, lines 28-55) - POST
  server fn; args `user_id: i64, new_status: String`; updates a single user's
  status.
